# ドメインイベント仕様

各ドメインが「何をきっかけに，どう振る舞うか」を定義する．
イベントは **発生 → 状態変化 → 副作用** の連鎖として表現し，RAG エンジン・分析ロジック・通知システムが
これを購読（Subscribe）することで，プラットフォーム全体の一貫性を保つ．

### イベント処理の保証事項

| 項目 | 方針 |
|---|---|
| **順序保証** | 同一エンティティ（同一 `企業` ID 等）に対するイベントは発生順に処理する（per-entity 順序保証）．異なるエンティティ間は並列処理可 |
| **べき等性** | 同一イベント ID の重複受信は無視する（exactly-once セマンティクス） |
| **結果整合性** | 副作用（下流エンティティの更新）は最終的整合性（Eventual Consistency）で処理する．同時更新が競合した場合は楽観的ロック（バージョン番号）で解決 |
| **失敗時の挙動** | 処理失敗イベントはデッドレターキューに格納し，人手レビューを促す通知を生成する |

## 1. 企業

企業はプラットフォームの中心エンティティであり，最も多くのイベントを発生させる．

| イベント名 | トリガー条件 | 主な状態変化 | 副作用（下流） |
|---|---|---|---|
| `企業登録` | 新規企業が登録された | `ステータス = active` | `投資家` / `市場` へ通知 |
| `上場確定` | 株式市場への上場が確定 | `上場フラグ = true`，`上場` レコード作成 | `証券登録` イベント発火 |
| `上場廃止` | 上場廃止（倒産・非公開化等） | `上場フラグ = false`，`上場.ステータス = 廃止` | `持分保有` の評価停止 |
| `合併クロージング` | M&A クロージング | 存続会社に `事業区分` が統合 | `持分保有` 再計算 |
| `事業分離` | 事業分離完了 | 新 `企業` 作成，`事業区分` 移管 | 新規持分計算 |
| `法人消滅` | 法人格消滅 | `ステータス = dissolved`，`解散日` 設定 | 全 `持分保有` を終了状態に |
| `経営陣交代` | CEO/CFO 等の交代発令 | `役員.退任日` 設定，新 `役員` 作成 | `仮説` 再評価トリガー |
| `事業再編` | 事業セグメントの統廃合 | `事業区分.終了日` 更新 / 新規作成 | `指標` の集計基準変更通知 |

---

## 2. 投資家

投資家は企業に資本を配分し，ポートフォリオを管理する主体である．

| イベント名 | トリガー条件 | 主な状態変化 | 副作用（下流） |
|---|---|---|---|
| `出資完了` | 出資・株式取得が完了 | `持分保有` 作成，`投資取引` 記録 | `資金調達ラウンド` 更新 |
| `持分増加` | 持分比率が増加 | `持分保有.持分比率` 更新 | `監視ルール` 閾値チェック |
| `持分減少` | 持分比率が減少 | `持分保有.持分比率` 更新 | `監視ルール` 閾値チェック |
| `完全売却` | 持分をゼロまで売却 | `持分保有` を終了状態に | `推奨アクション` ステータス更新 |
| `ラウンドクロージング` | ラウンドのクロージング | `資金調達ラウンド.ステータス = closed` | `企業` の投資後バリュエーション確定 |
| `評価額更新` | ポートフォリオ評価額の更新 | `バリュエーション` 更新 | `シナリオ.確率` 再評価トリガー |

---

## 3. 市場

市場は複数企業・製品が競合する空間であり，外部環境の変化を捉える．

| イベント名 | トリガー条件 | 主な状態変化 | 副作用（下流） |
|---|---|---|---|
| `シェア変動` | シェアの変動が観測された | `指標`（シェア）追加 | `競合関係.根拠` 更新トリガー |
| `価格変動` | 製品・サービスの価格変動 | `指標`（価格）追加 | `指標`（粗利率等）の再計算トリガー |
| `新規参入検知` | 新規プレイヤーの参入 | `競合関係` 新規作成 | `リスク`（競争リスク）の更新 |
| `競合撤退検知` | 競合の撤退 | `競合関係.有効終了日` 更新 | シェア `指標` の再集計 |
| `規制変更公示` | 規制当局による規則変更 | `コーポレートイベント`（規制）作成 | `リスク` 更新，`仮説` の棄却条件チェック |

---

## 4. 財務・開示

定期的な財務報告と修正申告がシステムに与えるイベント．

| イベント名 | トリガー条件 | 主な状態変化 | 副作用（下流） |
|---|---|---|---|
| `開示書類公表` | 有価証券報告書・決算短信が公開 | `開示書類` 作成，`財務諸表` / `財務数値` 生成 | `指標` の再計算トリガー |
| `業績サプライズ` | 実績が市場コンセンサスを大幅に上回る / 下回る | `指標.値タイプ = surprise` として記録 | `仮説` のステータス更新 |
| `業績修正` | 過去期財務数値の訂正 | `財務数値.正規化値` 再計算，訂正フラグ付与 | 関連 `指標` の再計算 |
| `業績予想発表` | 会社側の業績予想（ガイダンス）発表 | `業績予想` 作成 | `シナリオ.確率` 再評価，`仮説` チェック |
| `業績予想修正` | ガイダンスの上方 / 下方修正 | 既存 `業績予想` を更新 | `監視ルール` の再評価 |

---

## 5. リスク・ESG

企業のリスクプロファイルと ESG 評価が変化するイベント．

| イベント名 | トリガー条件 | 主な状態変化 | 副作用（下流） |
|---|---|---|---|
| `リスク認識` | 新たなリスクが認識された | `リスク` 作成（`ステータス = open`） | `監視ルール` の生成トリガー |
| `リスク格上げ` | 発生可能性または影響度が閾値を超過 | `リスク` 更新 | `推奨アクション` の再評価 |
| `リスク軽減` | 対策完了によりリスクが低下 | `リスク.ステータス = mitigated` | 加重リスクスコア再計算 |
| `訴訟開始` | 訴訟・行政手続きの開始 | `コーポレートイベント`（訴訟）作成，`リスク` 生成 | `ESG指標` 更新 |
| `ESG格付け変更` | ESG 格付けの変更 | `ESG指標` 更新 | `投資家` の投資戦略チェック |

---

## 6. 分析・意思決定

投資家の意思決定プロセスにおけるイベント．

| イベント名 | トリガー条件 | 主な状態変化 | 副作用（下流） |
|---|---|---|---|
| `投資仮説作成` | 投資仮説の新規作成 | `投資仮説` 作成（`ステータス = draft`） | `仮説` 分解，`シナリオ` 初期化 |
| `仮説確認` | 仮説の検証条件が満たされた | `仮説.ステータス = confirmed` | `投資仮説.スタンス` 強化，`推奨アクション` 更新 |
| `仮説棄却` | 仮説の棄却条件が成立 | `仮説.ステータス = falsified` | `投資仮説.スタンス` 弱化，`監視ルール` 更新 |
| `シナリオ確率更新` | シナリオ確率の更新 | `シナリオ.確率` 更新 | `バリュエーション` 再計算トリガー |
| `バリュエーション完了` | バリュエーション計算完了 | `バリュエーション` 作成 | `推奨アクション` 生成トリガー |
| `推奨アクション発行` | 投資推奨の確定 | `推奨アクション` 作成 | `監視ルール` の起動 |
| `監視ルール発動` | トリガー条件を満たすイベントが発生 | `監視ルール.ステータス = triggered` | `推奨アクション` の再検討通知 |

## 7. エビデンス（RAG基盤）

RAG（Retrieval-Augmented Generation）パイプラインにおけるイベント．

| イベント名 | トリガー条件 | 主な状態変化 | 副作用（下流） |
|---|---|---|---|
| `文書取り込み` | 新しいソースドキュメントが取り込まれた | `原典文書` 作成，`文書チャンク` 分割 | 抽出処理のキュー投入 |
| `クレーム抽出完了` | LLM による情報抽出完了 | `抽出クレーム` 生成，`エビデンスリンク` 作成 | 対応 `財務数値` / `指標` / `リスク` へのリンク付け |
| `エビデンスリンク確定` | クレームと既存エンティティの紐付け完了 | `エビデンスリンク` 確定 | `指標` / `リスク` の信頼度更新 |
| `原典文書失効` | ソースドキュメントが失効（訂正・削除等） | `原典文書.ステータス = obsolete` | 関連 `エビデンスリンク` の信頼度引き下げ |
